  <name>Task 1: Implement Sign Up and Login E2E Tests</name>
  <files>cypress/e2e/auth/signup.cy.js, cypress/e2e/auth/login.cy.js</files>
  <read_first>
    - Controllers/UserController.cs (understand signup/login endpoints and error handling)
    - Views/User/SignUpView.cshtml (identify form fields and error message selectors)
    - Views/User/LogInView.cshtml (identify form fields and error message selectors)
    - cypress/support/commands.js (use custom commands for signup/login)
    - cypress/fixtures/users.json (use test data)
  </read_first>
  <action>
1. Create cypress/e2e/auth/signup.cy.js:
   - describe('Sign Up')
   - it('should sign up with valid credentials'): Use cy.signup() with newUser fixture, verify redirect to home, verify username appears in UI
   - it('should show error for duplicate email'): Sign up with existing email, verify error message appears
   - it('should show error for invalid email format'): Enter invalid email, verify validation error
   - it('should show error for weak password'): Enter weak password, verify validation error

2. Create cypress/e2e/auth/login.cy.js:
   - describe('Login')
   - it('should login with valid credentials'): Use cy.login() with validUser fixture, verify redirect to home
   - it('should show error for invalid credentials'): Login with wrong password, verify error message "Invalid email or password"
   - it('should show error for non-existent user'): Login with non-existent email, verify error message
   - it('should redirect to home if already authenticated'): Login, then visit /user/log-in, verify redirect to home

3. Use cy.session() for tests that need authenticated state to avoid repeated login UI interactions
  </action>
  <verify>
    <automated>npx cypress run --spec cypress/e2e/auth/signup.cy.js,cypress/e2e/auth/login.cy.js</automated>
  </verify>

    - login.cy.js contains at least 4 test cases (valid, invalid, non-existent, already authenticated)
    - All tests use cy.signup() and cy.login() custom commands
    - Error messages match actual error messages from UserController.cs
    - Tests verify redirect to home after successful auth
    - Tests verify error messages appear for invalid inputs
  </acceptance_criteria>
  <done>Sign up and login E2E tests cover all positive and negative scenarios</done>

<task type="auto">
  <name>Task 2: Implement Logout and Session-Aware UI Tests</name>
  <files>cypress/e2e/auth/logout.cy.js, cypress/e2e/auth/session.cy.js</files>
  <read_first>

    - cypress/support/commands.js (use cy.logout() command)
    - cypress/e2e/auth/login.cy.js (reference for login patterns)
  </read_first>
  <action>
1. Create cypress/e2e/auth/logout.cy.js:
   - describe('Logout')
   - it('should logout and redirect to login page'): Login, click logout, verify redirect to /user/log-in
   - it('should clear session on logout'): Login, logout, visit protected page, verify redirect to login
   - it('should show login page after logout'): Logout, verify login form is visible

2. Create cypress/e2e/auth/session.cy.js:
   - describe('Session-Aware UI')
   - it('should show logout button when authenticated'): Login, verify logout button is visible in navbar
   - it('should hide sign-in/sign-up links when authenticated'): Login, verify sign-in and sign-up links are not visible
   - it('should show sign-in/sign-up links when not authenticated'): Visit home without login, verify sign-in and sign-up links are visible
   - it('should hide logout button when not authenticated'): Visit home without login, verify logout button is not visible
   - it('should maintain session across page refreshes'): Login, refresh page, verify still authenticated (logout button visible)
  </action>
  <verify>
    <automated>npx cypress run --spec cypress/e2e/auth/logout.cy.js,cypress/e2e/auth/session.cy.js</automated>
  </verify>

    - session.cy.js contains at least 5 test cases (logout button visible, sign-in hidden, sign-in visible, logout hidden, session persistence)

    - Tests verify actual UI element visibility based on auth state
